# @thomasfosterau/effect-sparql-node

## 0.1.0

### Minor Changes

- [#82](https://github.com/thomasfosterau/effect-rdf/pull/82) [`2ab97ef`](https://github.com/thomasfosterau/effect-rdf/commit/2ab97efe72297eab968a16f17acad90c3e941ab8) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - The CLI is built with `effect/cli`: generated `--help`, `--version` and shell completions, typed flags, and every flag backed by a `SPARQL_SERVER_*` environment variable through `Config` (a flag wins over the environment, which wins over the default). The flag names and their behaviour are unchanged; `--base-url` must now be an absolute IRI. New exports: `Cli.command`, `Cli.config`, `Cli.Flags`, `Cli.toArguments` and `Cli.envPrefix`; `Cli.run` takes an optional `{ version }`.

- [#94](https://github.com/thomasfosterau/effect-rdf/pull/94) [`8b26c37`](https://github.com/thomasfosterau/effect-rdf/commit/8b26c37aba87fc900ab11bb4680f98c33b64d48d) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Describe the SPARQL 1.1 Protocol and Graph Store HTTP Protocol as an Effect `effect/http-api` definition ([#60](https://github.com/thomasfosterau/effect-rdf/issues/60)).

  - Server: `SparqlApi` is the `HttpApi` (groups `sparql` and `graphStore`) with every request and response media type, the protocol's error statuses and `openApi` for its OpenAPI document; `SparqlApiBuilder.layerRoutes` serves it with `HttpApiBuilder`, delegating to the existing protocol code so behaviour is identical (the conformance suites run against both servers), with fallback routes for `405`, CORS preflights and direct graph identification; `SparqlApiBuilder.makeTestClient` is an in-process client for those routes.
  - Client: `SparqlApiClient` is a client derived from `SparqlApi` with `HttpApiClient`, with helpers that parse results and graphs (`results`, `construct`, `update`, `readGraph`, `writeGraph`), alongside the hand-written `SparqlClient`.

  `effect/http-api` is `@stability unstable` in Effect 4.

- [#125](https://github.com/thomasfosterau/effect-rdf/pull/125) [`2dba0a9`](https://github.com/thomasfosterau/effect-rdf/commit/2dba0a9acb4894c9050321d738b69e9e99d71e89) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - New package: the Node side of `@thomasfosterau/effect-rdf/sparql`. `NodeSparqlServer.layer` / `layerMemory` serve effect-rdf's platform-neutral `SparqlServer` on a `node:http` socket (through `@effect/platform-node`); `Cli` and the `effect-sparql-server` executable serve RDF files from the command line; `SparqlApi` describes the SPARQL 1.1 Protocol and Graph Store HTTP Protocol as an Effect `HttpApi` (with its OpenAPI document), served by `SparqlApiBuilder` (`makeTestClient` is an in-process client for its routes) and with the derived `SparqlApiClient`. Peers: `effect` `^4.1.2` (its `@effect/platform-node` 4.1.2 dependency requires it, and `SparqlApi` uses 4.1's list of content types per response stream) and `@thomasfosterau/effect-parse` `^0.4.0`. Service keys: `@thomasfosterau/effect-sparql-node/SparqlApiClient` and `…/SparqlApi/SchemaFallback`.
